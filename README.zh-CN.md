# 多助手协作模板

[English](README.md)

把这套文件放进项目后，可以在不同 AI 助手之间接力。遇到重要问题时，从同一个节点让本轮指定的助手各自完成任务，交齐再互评，最后由你拍板。

## 五步开始

1. **选择入口。** 新项目直接用这套模板。旧项目只导入核心文件，先让一个助手整理已有任务、进度和全部可取得的项目会话，再接入其他助手。[新项目启用与旧项目导入](collaboration/ONBOARDING.md)
2. **日常接力。** [PROJECT.md](PROJECT.md) 记录当前节点、已有证据和下一步。换助手时说「从主线继续」。
3. **指定本轮参与者。** 比如「从 N03 分岔，请 Claude Code、Gemini CLI 和 Cursor 参加」。当前助手在节点清单登记名单，固定共同材料和验收标准。为每位参与者打开一个新会话，让它们都从同一个节点开始。
4. **交齐后互评。** 指定的助手都交付后，你说「开放 N03 互评」。双方或多方可以直接查彼此的交付和已导出的对话原文。
5. **由你拍板。** 你告诉任意一位负责合并的助手采用哪些项。它复核后更新主线和归档索引。另一位下次接手只需要说「从主线继续」。

## 安装到旧项目

从一份新下载或克隆的模板目录运行下面两条命令。第一条预览要改哪些文件，第二条应用安装：

```sh
python tools/install.py "旧项目文件夹路径"
python tools/install.py "旧项目文件夹路径" --apply
```

使用 Python 3.11 或更新版本。安装会保留旧项目已有的规则、进度和归档。装好后，对一个助手说「导入旧项目」，让它整理可取得的历史。新项目可以直接使用 GitHub 的 **Use this template**。[完整导入步骤](collaboration/ONBOARDING.md)

## 用到哪些文件

- **[项目主线](PROJECT.md)** 保存进度、决定和下一个接手点。
- **[共用规则](AGENTS.md)** 写明助手何时读取、落盘、开放和合并。
- **[目录和模板](collaboration/GUIDE.md)** 说明每个节点的名单、状态、材料和分支怎么放。
- **[总对话归档](collaboration/ARCHIVE.md)** 索引主线和分支原文。原文放在对应目录，日常按需读。
- **[参与名单示例](collaboration/PARTICIPANTS.md)** 列出终端、编辑器和手动接入的选法。
- **[完整虚构示例](examples/report-layout/N03/)** 展示六位助手参加同一轮、互评和合并的记录。
- **[接入与兼容性](collaboration/COMPATIBILITY.md)** 说明多种客户端如何读取共用规则，以及哪些环节已经验证。

独立阶段按明确的读取范围执行。要强制隔离，请使用有访问权限边界的工作区。所有候选都用同一份起始材料。项目的实时对话、节点和分支产物建议使用默认的本地目录，示例是虚构的。

## 可选检查工具

Python 3.11 以上即可。检查工具读取名单和交付状态，并核查开放互评及合并所需记录。

```sh
python tools/check_node.py examples/report-layout/N03
python -m unittest discover -s tests -v
```

这套检查能验证本地文件流程。各客户端的会话导出与实际互读情况见 [兼容性记录](collaboration/COMPATIBILITY.md)。
